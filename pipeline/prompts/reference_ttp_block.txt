# 参考動画の構成スケルトン（TTP・厳密写像モード / 唯一の最上位ブロック）

**本ブロックが常に最上位の指示です。** 他ブロック（商品モード・angle・スタイル指示）と
矛盾したら必ず本ブロックの構成・構図・カメラワーク・色調・カット割り・リズムを優先し、
他ブロックはその制約内で従属的に扱ってください。

以下のスケルトンは参考動画 (reference_spec v2) から機械的に抽出して目標尺
（{TARGET_DURATION}秒）へスケールしたものです。**shots の数・各 duration_sec・
caption_in_offset_sec / caption_out_offset_sec / telop_style_hint・reference_visual・
sfx_plan・hook_end_shot_id / cta_start_shot_id は絶対に変更しないこと。**
LLM の役割は各 shot の `narration_jp` / `caption_jp` / `visual_prompt`（英語）の3フィールドを
埋めることだけです。骨（構成）は既に決まっています。

## 絶対厳守のルール
1. **shots の要素数を増減しない**。各 shot の id 名も変更しない。
2. 各 shot の `duration_sec` / `caption_in_offset_sec` / `caption_out_offset_sec` /
   `telop_style_hint` / `reference_visual` / `motion_preset` / `motion_intensity` /
   `scene_id` はスケルトンの値をそのまま返すこと。
   （**特に motion_preset は参考動画の光学フロー機械判定に基づくマッピング結果です。
   絶対に変更しないこと。**）
3. `sfx_plan` / `hook_end_shot_id` / `cta_start_shot_id` もスケルトンの値をそのまま返すこと。
4. **文言の丸写し禁止**: 参考動画のテロップ・字幕の語句を **15字以上連続して一致させないこと**
   （著作権侵害）。表現は必ず自分の言葉に言い換える。参考テロップは telop_style_hint
   （position/color/size_class）のスタイル参考としてのみ扱い、実文言は自分の言葉で書き直すこと。
5. **数字・事実は自分の題材から**: 参考動画に出てくる数値・期間・価格・体験の事実を流用しないこと
   （他人の実績流用は誤情報になる）。同じ「数字の使い方・置き場所」だけを真似て、
   中身は今回のテーマに即した自然な値にする。
6. **法令適合への翻訳**: 参考動画が薬機法・景表法違反の断定表現（「治る」「絶対」「必ず」等）を
   使っていたとしても、それをそのまま真似しないこと。同じ熱量・勢いは保ちながら、
   「私の場合は」の個人の体験・使用感の範囲に翻訳して書き直すこと。
7. `caption_jp` は 30字以内(25字以内推奨)。`narration_jp` は音読で対応 shot の duration_sec 秒前後に
   なる長さにする。全 shots の narration_jp を出現順に連結した
   文字列が `narration_script` と完全一致すること。
   **【telop 数はスケルトン固定・追加削除禁止】**: スケルトンで `caption_in_offset_sec`
   が付いている shot だけに `caption_jp` を入れる。それ以外の shot は `caption_jp=""`
   （空文字）で返すこと。**telop 数（caption を持つ shot 数）はスケルトンと完全一致**
   でなければならない（1個でも増減させると不合格）。参考動画のテロップは参考の実カット
   分布に沿って既に選定済みで、これを LLM が編集することは禁止（telop_iou が大きく崩れる）。
   **【narration_jp 文字数バジェット・F13・厳守】**: 各 shot の `narration_jp` は
   `expected_narration_chars`（無ければ 尺×既定 6.5字/秒）× **+15% までを絶対上限**とする
   （例: expected=15 なら **17字までで不合格ライン**。20字はアウト）。**超過すると自動不合格**
   になり、矯正リトライで書き直しを強制される。理由: LLMの文が長いと TTS 実尺が伸び、
   音声主導同期モードで shot が引き伸ばされ、**参考動画のカット割り・テロップ位置が全て崩れる**
   （telop_iou / cut_match が壊滅する）。対処: 冗長表現（「〜のように」「そして」「けれども」
   「さらに」「実は」「やはり」「ちなみに」「〜という感じで」）を全て削り、断定・体言止め・
   短い動詞句で書く。**話速の合わせ方（F7 参考リズム写像）**: skeleton の
   `narration_rhythm.chars_per_sec`（参考動画の実測話速）と `narration_rhythm.avg_gap_sec` を
   前提の話速として使う。`avg_gap_sec` が大きい参考動画（0.6秒以上）は「間」を大きく取る
   参考なので、shot境界を跨いだ文長を短めに設計すること。

## visual_prompt を書くときの最重要ルール（F10: 参考映像の忠実再現）
- 各 shot に含まれる `reference_visual`（`desc_en` / `framing` / `location` /
  `camera_move` / `shot_size` / `color_mood` / `lighting` / `color_palette_hex`）は
  **参考動画の実映像から抽出した根拠**です。visual_prompt は必ずこの値を第一の
  根拠として構成すること。
- 具体的には visual_prompt の英文に、`reference_visual.location`（撮影場所・
  ロケーション）・`framing` または `shot_size`（構図・被写体距離）・`camera_move`
  （カメラワーク）・`color_mood`（色調）を必ず語彙として含めること。
- テーマに合わせて内容（人物/物体/題材）だけを置換し、ロケーション・構図・
  カメラワーク・色調は参考動画に一致させること。参考が料理シーンなら kitchen /
  食材、旅行シーンなら outdoor / 景色、Minecraft の俯瞰なら aerial high-angle と
  いった具合に、参考の実映像に忠実な語彙を使うこと。
- `reference_visual` が空・欠落している shot に限り、director_prompt.txt の
  「UGC 生活感」フォールバックに従う。それ以外の shot で美容UGC 固定テンプレ
  （bathroom / drugstore shelf 等）を強制しないこと。
