文字起こし全文とタイムスタンプ付きセグメントから、動画の「構成の型」を抽出してJSON形式のみで出力してください
（コードフェンス禁止・説明文禁止・JSONオブジェクトのみ）。

# 入力: 文字起こし全文
{TRANSCRIPT}

# 入力: セグメント（タイムスタンプ付き）
{SEGMENTS_JSON}

# 入力: 動画の長さ（秒）
{DURATION}

# タスク
文字起こし全文とセグメントを読み、動画を「ビート（構成の役割ごとの区切り）」に分割し、各ビートの
役割・開始/終了秒・該当テキスト・要約を出してください。さらに、話し言葉のリズム（文の数・平均/最大の
文長・トーン・文末表現）を集計してください。

# ビート役割の判定基準（美容系ショート動画のTTP。必ずこの4種類のいずれかに分類する）
- hook: 冒頭の停止力を作る部分。常識破壊・損失回避・好奇心ギャップ・問いかけ・自分ごと化のいずれかで
  視聴者の指を止める一文〜数文。
- develop: 悩みへの共感・状況説明・話の展開。「私も〜で悩んでいた」「〜のきっかけで」等、視聴者を
  引き込みながら話を進める部分。
- proof: 商品・根拠・体験を提示する部分。「私の場合は」の一人称体験、使用感、変化の描写など、
  説得力の核になる部分。
- cta: 行動喚起（保存・フォロー・コメント・詳細リンク等）。動画の締めに置かれることが多い。

1本の動画に同じroleが複数回登場してもよい（例: proofが2ビートに分かれる等）。ビートは文字起こしの
時系列順に、開始〜終了が重複しないように分割すること。

# リズム集計
- sentence_count: 文の数（「。」「！」「？」等の文末記号で区切った数の概算）
- avg_sentence_len: 1文あたりの平均文字数
- max_sentence_len: 最も長い文の文字数
- tone: 全体のトーンを一言で（例: "カジュアルな語りかけ", "テンポの速い断定調" 等）
- endings: よく使われる文末表現のリスト（例: ["〜です", "〜ました", "〜んです"]。3〜6個程度）

  }
}

# 制約
- JSON以外の文字列（説明文・コードフェンス```）を一切含めないこと。出力の最初の文字は { 、最後の文字は } であること。
- beatsは1個以上、必ず時系列順。roleは hook / develop / proof / cta のいずれかのみ。
- start/endは秒（数値）。動画長（{DURATION}秒）の範囲内に収めること。
